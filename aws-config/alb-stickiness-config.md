# ALB Session Affinity Configuration for ECS Fargate
## Remediation for cz-java-0069: In-Memory Session Storage

### Overview
This document describes the transitional strategy for deploying the ResortsLite application 
on AWS ECS Fargate with Application Load Balancer (ALB) session affinity (stickiness).

While the application has been refactored to use stateless JWT authentication, enabling ALB 
target group stickiness provides a low-effort transitional measure to minimize session 
disruption during the migration period.

### Configuration Requirements

#### 1. ALB Target Group Stickiness Settings
- **Stickiness Type**: `lb_cookie` (Application Load Balancer generated cookie)
- **Stickiness Duration**: `3600 seconds` (1 hour, matching JWT token expiration)
- **Cookie Name**: Auto-generated by ALB (AWSALB)

#### 2. Terraform Configuration

```hcl
resource "aws_lb_target_group" "resorts_lite" {
  name     = "resorts-lite-tg"
  port     = 8080
  protocol = "HTTP"
  vpc_id   = var.vpc_id
  target_type = "ip"  # Required for ECS Fargate

  health_check {
    enabled             = true
    healthy_threshold   = 2
    unhealthy_threshold = 2
    timeout             = 5
    interval            = 30
    path                = "/actuator/health"
    protocol            = "HTTP"
    matcher             = "200"
  }

  stickiness {
    enabled         = true
    type            = "lb_cookie"
    cookie_duration = 3600  # 1 hour to match JWT expiration
  }

  deregistration_delay = 30

  tags = {
    Name        = "resorts-lite-target-group"
    Application = "ResortsLite"
    Environment = var.environment
    ManagedBy   = "Terraform"
  }
}

resource "aws_lb_listener_rule" "resorts_lite" {
  listener_arn = var.alb_listener_arn
  priority     = 100

  action {
    type             = "forward"
    target_group_arn = aws_lb_target_group.resorts_lite.arn
  }

  condition {
    path_pattern {
      values = ["/api/*"]
    }
  }
}
```

#### 3. AWS CLI Configuration

```bash
# Create target group with stickiness
aws elbv2 create-target-group \
  --name resorts-lite-tg \
  --protocol HTTP \
  --port 8080 \
  --vpc-id vpc-xxxxxxxxx \
  --target-type ip \
  --health-check-enabled \
  --health-check-path /actuator/health \
  --health-check-interval-seconds 30 \
  --health-check-timeout-seconds 5 \
  --healthy-threshold-count 2 \
  --unhealthy-threshold-count 2

# Enable stickiness on existing target group
aws elbv2 modify-target-group-attributes \
  --target-group-arn arn:aws:elasticloadbalancing:region:account-id:targetgroup/resorts-lite-tg/xxxxxxxxx \
  --attributes \
    Key=stickiness.enabled,Value=true \
    Key=stickiness.type,Value=lb_cookie \
    Key=stickiness.lb_cookie.duration_seconds,Value=3600 \
    Key=deregistration_delay.timeout_seconds,Value=30
```

#### 4. CloudFormation Configuration

```yaml
ResortsLiteTargetGroup:
  Type: AWS::ElasticLoadBalancingV2::TargetGroup
  Properties:
    Name: resorts-lite-tg
    Port: 8080
    Protocol: HTTP
    VpcId: !Ref VpcId
    TargetType: ip
    HealthCheckEnabled: true
    HealthCheckPath: /actuator/health
    HealthCheckIntervalSeconds: 30
    HealthCheckTimeoutSeconds: 5
    HealthyThresholdCount: 2
    UnhealthyThresholdCount: 2
    TargetGroupAttributes:
      - Key: stickiness.enabled
        Value: 'true'
      - Key: stickiness.type
        Value: lb_cookie
      - Key: stickiness.lb_cookie.duration_seconds
        Value: '3600'
      - Key: deregistration_delay.timeout_seconds
        Value: '30'
    Tags:
      - Key: Name
        Value: resorts-lite-target-group
      - Key: Application
        Value: ResortsLite
```

### How It Works

1. **Client Request**: When a client makes the first request to the application through the ALB, 
   the ALB generates a cookie (AWSALB) and sends it to the client.

2. **Cookie Persistence**: The client's browser stores this cookie and includes it in subsequent requests.

3. **Request Routing**: The ALB reads the AWSALB cookie and routes the request to the same ECS task 
   that handled the initial request, ensuring session continuity.

4. **JWT Authentication**: The application uses JWT tokens for stateless authentication, so even if 
   a request is routed to a different task, it will still work correctly.

5. **Transitional Period**: The stickiness provides a safety net during the migration period, 
   reducing the risk of session-related issues while the stateless architecture is validated.

### Benefits

- **Low Effort**: No application code changes required
- **Backward Compatible**: Works with both stateful and stateless patterns
- **Gradual Migration**: Allows time to validate the JWT-based stateless architecture
- **Reduced Risk**: Minimizes disruption during the containerization migration

### Migration Path

1. **Phase 1 (Current)**: Deploy with ALB stickiness enabled
   - Application uses JWT tokens for authentication
   - ALB stickiness provides additional safety net
   - Monitor application behavior and validate stateless operation

2. **Phase 2 (Future)**: Disable ALB stickiness
   - Once stateless operation is validated in production
   - Remove stickiness configuration from target group
   - Application continues to work with pure stateless JWT authentication
